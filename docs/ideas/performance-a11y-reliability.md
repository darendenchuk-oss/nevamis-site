# Performance, Accessibility and Reliability — 55 improvements

Written 2026-07-27 against the real repo state: `nevamis-site` (static, GitHub Pages, no build step) and `nevamis-engine` (Next.js on Vercel). The site already does a great deal right — self-hosted fonts, a `.skip` link, `:focus-visible` styling, a WCAG 2.2.2 motion toggle, `html.no-js` fallbacks, guarded init in `assets/motion/main.js`, a first-party analytics endpoint with an origin allowlist and a name allowlist, a real `/api/health` probe, and 37 Playwright specs. So the list below is not "add the basics"; it is the next layer down, found by reading the actual bytes. Several items are outright bugs (the play button's accessible name never changes; three byte-identical Bricolage font files are served under different URLs; a 1.3 MB `three.module.js` ships to production for three dead concept pages; the inline tail script strips `no-js` *before* `site.js` proves it loaded). The theme throughout: this is a sales site whose only job is to survive a trades owner's mid-range Android on a job-site LTE connection, and whose demo line is the single most load-bearing asset in the business. Fix the things that make it fall over in front of a prospect first; polish second.

---

1. **PERFORMANCE-A11Y-RELIABILITY-001 — Collapse the three byte-identical Bricolage font files into one variable face.** `md5sum assets/fonts/*.woff2` proves `bricolage-grotesque-500-latin.woff2`, `-700-latin.woff2` and `-800-latin.woff2` are the same 76,888 bytes (`ad33cbc6d23292050f1f2010848ab619`), and the three `-latin-ext` files are likewise identical at 30,736 bytes. Because `assets/fonts/fonts.css` points each weight at a different URL, a page using both 500 (the `.wordmark span`) and 700 (`h1/h2/h3`) downloads 153,776 bytes of identical data. Replace all six declarations with two `@font-face` rules pointing at one file each, using `font-weight: 500 800;` — saves ~77 KB on first paint with zero visual change.
   impact 4/5 · effort 1/5 · touches: assets/fonts/fonts.css, assets/fonts/*.woff2

2. **PERFORMANCE-A11Y-RELIABILITY-002 — Delete the duplicate, shadowed `@font-face` blocks in fonts.css.** Lines ~85–125 of `assets/fonts/fonts.css` declare Bricolage weight 700 and 800 pointing at the **500** files, and a later block (added "2026-07-27 for the motion redesign") re-declares the same weight/style/unicode-range pairs pointing at the 700/800 files. The later ones win, so the first pair is dead CSS that only exists to confuse the next person editing the file. Remove the shadowed declarations when doing 001 so there is one rule per weight.
   impact 2/5 · effort 1/5 · touches: assets/fonts/fonts.css

3. **PERFORMANCE-A11Y-RELIABILITY-003 — Preload the two first-paint font files and inline their `@font-face`.** Today the critical chain is HTML → `assets/fonts/fonts.css` → woff2, three sequential round trips before the `h1` can render in Bricolage. Inline the two faces the hero actually needs (Bricolage latin for `h1`, Atkinson 400 latin for `.lede`) into the existing `<style>` block in `home.html`, add `<link rel="preload" as="font" type="font/woff2" crossorigin>` for both, and leave `fonts.css` to load the rest. Removes one full RTT from LCP on every page.
   impact 4/5 · effort 2/5 · touches: home.html + all secondary .html heads, assets/fonts/fonts.css

4. **PERFORMANCE-A11Y-RELIABILITY-004 — Fix the wake-overlay LCP trap.** `#wake` is `position:fixed;inset:0` filled with `--navy-0` and is only cleared when the GSAP timeline runs; the inline safety net in `home.html` waits **2500 ms** before force-hiding it. On a slow connection where `assets/vendor/gsap.min.js` (72 KB) plus `MotionPathPlugin.min.js` (22 KB) plus six unbundled ES modules haven't landed, the visitor stares at an opaque black rectangle and Lighthouse measures LCP at the fade, not at the paint. Drop the safety net to 900 ms, and add a pure-CSS `animation: wakeFail 1.2s forwards` on `#wake` that GSAP cancels when it boots — so the fallback needs no JavaScript at all.
   impact 5/5 · effort 2/5 · touches: home.html (inline style + tail script), assets/motion/hero.js

5. **PERFORMANCE-A11Y-RELIABILITY-005 — Add `modulepreload` for the five motion ES modules.** `<script type="module" src="assets/motion/main.js">` imports `tokens.js`, `hero.js`, `cursor.js`, `aurora.js`, `sonar.js`, and `hero.js`/`cursor.js`/`aurora.js`/`sonar.js` each re-import `tokens.js`. Unbundled, that is a two-level waterfall the browser cannot see until `main.js` parses. Add five `<link rel="modulepreload" href="assets/motion/*.js">` tags to every page head so all six requests start in parallel — flattens ~200–400 ms off motion start on 4G, and directly shortens the `#wake` blackout from 004.
   impact 3/5 · effort 1/5 · touches: home.html and all page heads

6. **PERFORMANCE-A11Y-RELIABILITY-006 — Add `defer` to the two vendored GSAP script tags.** Every page ends with `<script src="assets/vendor/gsap.min.js"></script>` and `<script src="assets/vendor/MotionPathPlugin.min.js"></script>` with no `defer`, so 94 KB of parser-blocking JavaScript sits between the last paragraph of the page and `DOMContentLoaded` — which also delays the already-deferred `site.js` and `motion.js`. `defer` preserves execution order, so adding it to both is behaviour-identical and frees the parser.
   impact 3/5 · effort 1/5 · touches: home.html, pricing.html, pilot.html, demo.html, book.html, about.html, coming-soon.html, privacy.html, terms.html, revenue-engine.html, 404.html

9. **PERFORMANCE-A11Y-RELIABILITY-009 — Fix the example-call play button's accessible name.** In `home.html` the button is `<button class="play" id="playBtn" aria-label="Play the example call audio">` with an inner `<span id="playLabel">Hear this call</span>`. `site.js` swaps that span's text to "Pause" and back, but `aria-label` **overrides** the visible text, so a screen-reader user is always told "Play the example call audio" — even mid-playback — and the visible label "Pause" is not contained in the accessible name (WCAG 2.5.3 Label in Name, plus a 4.1.2 state mismatch). Delete the `aria-label`, move "Hear this call"/"Pause" into the span as the sole name source, and add `aria-pressed`.
   impact 4/5 · effort 1/5 · touches: home.html, demo.html, site.js

10. **PERFORMANCE-A11Y-RELIABILITY-010 — Debounce the ROI calculator's live region.** `site.js` binds `roiForm.addEventListener("input", calc)` and `calc()` unconditionally writes a full sentence into `#roiLive` (`aria-live="polite"`). Typing "400" into `#roiValue` fires three announcements; a screen-reader user gets a stream of interrupting estimates while still entering the number. Wrap the `#roiLive` write in a ~700 ms trailing debounce (keep the visible `#roiOpp`/`#roiRec` updates instant) so exactly one figure is spoken once the visitor stops typing.

Only write to the live region when the transition came from a user action (`#simWatch`, `[data-sim-fwd]`, `[data-sim-back]`, `[data-sim-replay]`) — track a `userDriven` flag and skip the write on timer ticks.
   impact 4/5 · effort 2/5 · touches: motion.js (simulator FSM), home.html

12. **PERFORMANCE-A11Y-RELIABILITY-012 — Add `scroll-padding-top` for WCAG 2.2 SC 2.4.11 (Focus Not Obscured).** `.site-header` is `position:fixed` at 68 px tall and `.callbar` is fixed to the bottom under 820 px, but `assets/motion/site.css` contains no `scroll-padding` or `scroll-margin` anywhere. Add `html{scroll-padding-top:88px;scroll-padding-bottom:96px}` plus `scroll-behavior:smooth` gated behind `@media(prefers-reduced-motion:no-preference)`. 18. **PERFORMANCE-A11Y-RELIABILITY-018 — Handle WebGL context loss in the aurora.** `assets/motion/aurora.js` falls back to the 2D painter only when `canvas.getContext('webgl')` returns null at init. On low-memory Android, Chrome routinely fires `webglcontextlost` *after* a successful init (tab backgrounded, GPU process restarted), leaving a frozen or blank fixed-position canvas over the whole page at `opacity:.9`. Add a `webglcontextlost` listener that calls `preventDefault()`, tears down the shader painter, and swaps in `init2DFallback(canvas)` — the fallback function already exists and is fully written.
   impact 3/5 · effort 2/5 · touches: assets/motion/aurora.js

19. **PERFORMANCE-A11Y-RELIABILITY-019 — Turn off `preserveDrawingBuffer` in production.** `initShader()` in `aurora.js` sets `preserveDrawingBuffer: true` with the comment that it "keeps toDataURL meaningful for the test harness." On many mobile GPU drivers that flag forces an extra full-framebuffer copy every frame, for a canvas that repaints continuously for the entire page session. Gate it: `preserveDrawingBuffer: new URLSearchParams(location.search).get('motionDebug') === '1'`, and set `?motionDebug=1` in the Playwright specs that screenshot the canvas.
   impact 3/5 · effort 1/5 · touches: assets/motion/aurora.js, tests/motion.spec.js

20. **PERFORMANCE-A11Y-RELIABILITY-020 — Give the aurora an adaptive frame budget.** The rAF loop in `aurora.js` runs for the life of the page at whatever rate the device offers, with no measurement of what it costs. Sample frame duration over the first 60 frames; if the median exceeds 12 ms, drop to a 30 fps paint interval, and if it exceeds 22 ms, paint one still frame and stop the loop entirely (the reduced-motion path already does exactly this — reuse it). A prospect on a three-year-old Android should get a fast page, not a beautiful sky.
   impact 4/5 · effort 3/5 · touches: assets/motion/aurora.js
