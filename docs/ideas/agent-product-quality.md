# Agent Product Quality — 60 Improvements

The AI receptionist is the one thing Nevamis actually sells today, and it is already in production: the demo agent `agent_9101ky43tys1fswstde818j7j8wt` on (587) 413-0035 (gemini-2.5-flash, temp 0.0, `eleven_flash_v2`, voice `gJx1vCzNCD1EQHT212Ls`, 12,131-character prompt, sha256 prefix `d24f1934`), plus the escalation line `agent_9601kybwnjswevwskwdv1ac66xvv` on (587) 209-2345. The supporting apparatus is unusually mature for a pre-revenue business — a 36-scenario test catalogue in `config/elevenlabs/nevamis-agent-test-cases.md`, a change-control loop in `nevamis-engine/docs/AGENT-CHANGE-CONTROL.md`, prompt snapshots with hashes in `nevamis-engine/docs/agent-prompts/`, a 15-check regression script, and nine post-call data-collection fields wired into `src/domain/call-intake.ts`. So the gaps are not "build more"; they are (a) a handful of real latent bugs that will bite a paying client, (b) the distance between the 36-scenario catalogue and the 4 scenarios actually automated, (c) capture accuracy on the details that decide whether a lead is usable, and (d) the fact that no real call has ever been scored (QUALITY-SCORECARD row 3 is RED). These 60 are ordered so the cheap correctness fixes come first, because a wrong booking on client number one costs more than every polish item below combined.

## A. Latent correctness and safety bugs

1. **AGENT-PRODUCT-QUALITY-001 — Kill the hard-coded `-06:00` booking offset before November.** The live demo prompt's BOOKING PROCEDURE step 4 instructs `book_meeting` to send "the start time in ISO 8601 with the -06:00 Mountain offset (for example 2026-07-25T09:00:00-06:00)". Edmonton is UTC-06:00 only during MDT; from the first Sunday in November to mid-March it is UTC-07:00, so every winter booking will land one hour off in Cal.com while the agent cheerfully confirms the wrong time out loud. Replace the literal offset with an instruction to use the offset supplied in a dynamic variable, and add a regression assertion that books a January date and checks the returned slot.
   impact 5/5 · effort 1/5 · touches: `config/elevenlabs/nevamis-live-agent-system-prompt.md` (BOOKING PROCEDURE step 4), live demo agent prompt, `nevamis-engine/scripts/agent-regression.mts`

2. **AGENT-PRODUCT-QUALITY-002 — Inject the current Edmonton date/time as a dynamic variable instead of trusting "your context".** Step 4 of the booking procedure says to use "today's date from your context", which is exactly the kind of implicit assumption that produces a booking for last Thursday. ElevenLabs supports dynamic variables on inbound calls; pass `current_datetime_edmonton` and `current_utc_offset` and rewrite the prompt to reference them explicitly, including for relative phrases like "tomorrow" and "next Tuesday". This single change removes the largest silent failure mode in the booking chain.
   impact 5/5 · effort 2/5 · touches: ElevenLabs agent config (dynamic variables), demo + client agent prompts, `nevamis-engine/docs/BOOKING-CHAIN-2026-07-27.md`

3. **AGENT-PRODUCT-QUALITY-003 — Add a Twilio fallback TwiML so an ElevenLabs outage records a voicemail instead of ringing out.** `AGENT-REGRESSION-2026-07-27.md` records this as a known unfixable limitation ("if the agent platform is down, calls ring unanswered — there is no voicemail fallback setting on EL-managed numbers"), but both numbers already enter through `nevamis.ca/ring.xml`, which is Nevamis-controlled TwiML that plays `ringback.mp3` then redirects to ElevenLabs. Set Twilio's *fallback* voice URL on both numbers to a second static file (`ring-fallback.xml`) containing `<Say>` plus `<Record>`, so a provider outage degrades to a recorded message rather than a dead line. For a client whose only phone line is forwarded to you, this is the difference between a bad day and a cancelled contract.
   impact 5/5 · effort 2/5 · touches: `nevamis-site/ring.xml` (new sibling file), Twilio number config, `nevamis-engine/docs/UPTIME-MONITORING-DECISION.md`

## B. Prompt and script craft

11. **AGENT-PRODUCT-QUALITY-011 — Capture the callback number in the first thirty seconds, before anything else.** Every prompt in the repo collects contact details *after* the conversation, at the ON EVERY CALL / BOOKING stage — so a call that drops at second forty produces nothing at all, which on a trades line (people call from trucks, basements and job sites) is a routine event. Add a rule near the top of the client template: after the caller states the problem in one sentence, say "before we go further, what's the best number if we get cut off?", capture it, and treat it as the minimum successful outcome of any call. This is the highest-value single line of prompt text on the whole product.
   impact 5/5 · effort 1/5 · touches: `config/elevenlabs/vertical-plumbing-agent-template.md`, `nevamis-engine/src/domain/agent-draft.ts`, demo agent prompt

12. **AGENT-PRODUCT-QUALITY-012 — Fix the qualification order to urgency-first.** The plumbing template collects name, number, address and problem in the order a form would, but for a trades receptionist urgency determines everything downstream: an emergency skips booking and goes straight to the approved fallback, a routine job goes to the calendar. Restructure the capture sequence to: one-sentence problem → urgency classification → callback number → address/service-area check → name → booking or message. It also makes the call feel like a competent dispatcher rather than a form being read aloud.
   impact 4/5 · effort 2/5 · touches: `config/elevenlabs/vertical-plumbing-agent-template.md` (BOOKING section), `nevamis-engine/src/domain/agent-draft.ts`

13. **AGENT-PRODUCT-QUALITY-013 — Cap the number of questions before a booking at five, and say so in the prompt.** Catalogue case 18 covers the long-winded caller but nothing bounds the agent's own question count, and the RESPONSE QUALITY block only limits questions per turn, not per call. Add: "You have at most five questions before you either book or take a message. If you still need more, take the message and let a human get the rest." Long interrogations are the number one reason a caller hangs up on an AI receptionist, and every extra question also burns connected minutes the client pays for.
   impact 4/5 · effort 1/5 · touches: client agent templates, `nevamis-engine/src/domain/agent-draft.ts`

14. **AGENT-PRODUCT-QUALITY-014 — Add a "repeat, don't guess" rule for noisy calls to the prompt itself.** The test plan's manual call #7 (call from a running vehicle) expects the agent to ask for repeats rather than guess, but no prompt anywhere contains that instruction — the behaviour is being tested for but never specified. Write it explicitly: "If any part of a name, number, or address was unclear, ask for it again. Never fill in a plausible-sounding guess. Two repeats is fine; a wrong number is not." Trades calls are disproportionately noisy, so this is a vertical-specific necessity, not a nicety.
   impact 4/5 · effort 1/5 · touches: all agent prompts, `config/elevenlabs/nevamis-agent-test-cases.md` (case 16/17 assertions)

15. **AGENT-PRODUCT-QUALITY-015 — Add a pacing rule for callers who are struggling.** Nothing in the prompts adapts speaking rate or sentence length for elderly callers, heavy accents, or people who repeatedly say "sorry, what?". Add a rule: if the caller asks you to repeat twice, slow down, shorten to one clause per turn, and offer to take a message instead of continuing the booking flow. It is a two-sentence prompt change that meaningfully widens who the product works for.
   impact 3/5 · effort 1/5 · touches: all agent prompts (HOW YOU SPEAK section)

16. **AGENT-PRODUCT-QUALITY-016 — Decide and write down the French-language policy.** Canada, Alberta, service business: some percentage of callers will open in French, and today the agent's behaviour is undefined — it may attempt French badly, or ignore it. Choose one: enable ElevenLabs multi-language on the model that supports it and test it properly, or add an honest single line ("I only speak English — I'll take your name and number and have someone call you"). Undefined is the only wrong answer.
   impact 3/5 · effort 2/5 · touches: ElevenLabs agent language config, all agent prompts, `config/elevenlabs/nevamis-agent-test-cases.md` (new case)

17. **AGENT-PRODUCT-QUALITY-017 — Add a spam and robocall fast path.** The demo line has a 300-call daily cap and client plans meter connected AI minutes (1,400 on the self-serve plans, 250 on Performance Partnership), so every silent auto-dialer, "your Google listing" pitch and duct-cleaning robocall that reaches the AI is billable minutes and polluted call data. Add a rule: if the caller is a recorded message, a sales pitch, or does not respond to the second prompt, give one short close and `end_call` within twenty seconds, and set `intent` to `spam` so those calls can be filtered out of the client's summary digest.
   impact 4/5 · effort 1/5 · touches: client agent prompts, `nevamis-engine/src/domain/call-intake.ts` (intent values), owner digest filtering

18. **AGENT-PRODUCT-QUALITY-018 — Add a wrong-number fast path.** The escalation agent already handles non-staff callers politely; client agents have no equivalent, so someone who dialled the wrong plumber gets taken through qualification. One sentence — confirm the business name, apologise, end the call — saves minutes, keeps the call log clean, and avoids a bewildering experience that the caller will describe to other people.
   impact 3/5 · effort 1/5 · touches: client agent templates, `nevamis-engine/src/domain/agent-draft.ts`

19. **AGENT-PRODUCT-QUALITY-019 — Standardize the close-out script: recap, next step, `end_call`.** ENDING THE CALL currently covers silence and goodbye but not the normal completion, so the last thing the caller hears varies run to run. Specify the shape: one sentence recapping what was captured or booked, one sentence naming exactly what happens next and who does it, then `end_call`. The recap is also free verification — it is the caller's last chance to correct a wrong number before the summary reaches the owner.
   impact 4/5 · effort 1/5 · touches: all agent prompts (ENDING THE CALL section)

20. **AGENT-PRODUCT-QUALITY-020 — Purge unpromisable timing language from every prompt.** `nevamis-engine/docs/SUPPORT-SLA.md` deliberately refuses to promise a client-side callback time, and the engine's draft builder already forbids it, but the language is not enforced anywhere else. Add "never say 'right away', 'within the hour', 'first thing tomorrow', or any specific callback time unless it is in the client's approved intake" to the NEVER block, and add a regression assertion that scans agent turns for those phrases. A cheerful invented promise is the fastest way to make a new client's customer angry at them, not at you.
   impact 4/5 · effort 1/5 · touches: client agent templates, `nevamis-engine/scripts/agent-regression.mts`, `nevamis-engine/docs/SUPPORT-SLA.md`

21. **AGENT-PRODUCT-QUALITY-021 — Consolidate and version the demo prompt, which has grown to 12,131 characters.** The audit already noted overlapping booking sections in the pre-upgrade prompt, and v2 kept both an OFFER TO BOOK and a BOOKING PROCEDURE block plus TOOL DISCIPLINE restating the same tool rules a third time. Do one editorial pass that removes restatement without removing a single rule, then measure whether the shorter prompt changes time-to-first-token (see idea 30). Add a `Version:` / `Changed:` header line and a short changelog at the bottom of `nevamis-live-agent-system-prompt.md` so prompt archaeology stops requiring hash comparisons.
   impact 3/5 · effort 3/5 · touches: `config/elevenlabs/nevamis-live-agent-system-prompt.md`, `nevamis-engine/docs/agent-prompts/demo.md`

22. **AGENT-PRODUCT-QUALITY-022 — Write the "what this AI cannot do" answer once, and use it everywhere.** Catalogue case 4 tests the graceful-unknown path and the site's comparison table sells honest fallback, but there is no canonical phrasing, so each run improvises. Draft three sentences — it does not guess, it says so plainly, it captures the question and the caller's details so a human answers, and the answer gets added so it knows next time — and put them verbatim in the demo prompt, the client templates, and the FAQ on `home.html`. Consistency here is a sales asset: prospects who hear the same honest answer on the phone that they read on the site trust both more.
   impact 4/5 · effort 1/5 · touches: demo + client prompts, `nevamis-site/home.html` (FAQ), `config/elevenlabs/nevamis-knowledge-base.md`

## C. Capture accuracy — the details that decide whether a lead is usable

23. **AGENT-PRODUCT-QUALITY-023 — Specify an email read-back protocol with letter-by-letter confirmation.** The demo prompt says "spell the email back to confirm it" with no method, and the single most common ASR failure on phone audio is exactly this (b/d/e/p/t/v/z, m/n, and "at gmail" vs "at g-mail"). Specify: read the local part letter by letter with a disambiguating word for ambiguous letters ("d as in delta"), say the domain as a whole word, and re-confirm once. Add the six most common Canadian domains — gmail, hotmail, outlook, yahoo, shaw.ca, telus.net — as a normalization list so the agent snaps near-misses to the right domain rather than booking to an address that bounces.
   impact 5/5 · effort 2/5 · touches: demo agent prompt (BOOKING PROCEDURE step 1), `config/elevenlabs/nevamis-agent-test-cases.md` (case 17)

24. **AGENT-PRODUCT-QUALITY-024 — Specify phone-number capture as three digit groups with an area-code default.** Catalogue case 16 tests a number given in spoken groups but the prompt gives no capture method. Specify: repeat back as three groups (area code, exchange, last four), and if the caller gives only seven digits, ask which of 587, 780 or 825 rather than assuming. Then add a validation rule — a captured number that is not ten digits is never sent to `notify_owner`; the agent asks again.
   impact 5/5 · effort 1/5 · touches: demo + client agent prompts, `nevamis-engine/src/domain/call-intake.ts`

25. **AGENT-PRODUCT-QUALITY-025 — Add address and service-area capture with a postal-code cross-check.** The plumbing template has `{{service_area}}` and an `service_area_result` data-collection field, but no capture procedure — the agent has to decide "is Beaumont in your area?" from a free-text list. Have it capture street address plus the first three characters of the postal code (the FSA), read the address back, and classify against an explicit FSA list per client rather than city names, which are ambiguous around Edmonton's ring of Sherwood Park, St. Albert, Spruce Grove, Leduc, Beaumont and Nisku. A truck sent to the wrong municipality is the most expensive capture error in the product.
   impact 4/5 · effort 3/5 · touches: `config/elevenlabs/vertical-plumbing-agent-template.md`, `nevamis-engine/src/domain/agent-draft.ts`, client intake form

26. **AGENT-PRODUCT-QUALITY-026 — Build a pronunciation and vocabulary lexicon for Edmonton trades calls.** The demo prompt already promises "even how it pronounces local street names" but nothing implements it. Assemble a lexicon of the terms that break ASR and TTS on these calls: place names (Whitemud, Nisku, Wetaskiwin, Namao, Anthony Henday, Callingwood), trade terms (eavestrough, HRV, ERV, weeping tile, sump, tankless, breaker panel, sil-cock), and brand names clients mention. Feed it into the agent's pronunciation dictionary and, where the platform supports keyword biasing, into ASR — this is one of the few genuinely local advantages a national competitor won't bother to build.
   impact 4/5 · effort 3/5 · touches: new `config/elevenlabs/pronunciation-lexicon-edmonton.md`, ElevenLabs agent pronunciation/ASR settings

27. **AGENT-PRODUCT-QUALITY-027 — Add a low-confidence capture flag and surface it in the summary.** `src/domain/agent-draft.ts` defines nine data-collection fields, none of which record how sure the agent was. Add `capture_confidence` ("high" when every load-bearing detail was read back and confirmed, "low" when anything was guessed, garbled or unconfirmed), and have the owner SMS/digest prefix low-confidence calls with "⚠ verify number". An owner who knows which two of yesterday's nine calls need double-checking trusts the system far more than one who is told all nine are perfect.
   impact 4/5 · effort 2/5 · touches: `nevamis-engine/src/domain/agent-draft.ts` (`DRAFT_DATA_COLLECTION`), `src/domain/call-intake.ts`, owner notification format

28. **AGENT-PRODUCT-QUALITY-028 — Handle mid-call corrections explicitly and test them.** The demo page advertises "change your mind mid-call" as a stump challenge and catalogue case 14 covers a changed date, but the prompt has no rule for corrections to already-captured fields. Add: when a caller corrects any detail, acknowledge the change in three words, restate only the corrected field, and treat the newest value as authoritative for every downstream tool call. Then automate case 14 so the advertised claim on `demo.html` is backed by a test that runs on every prompt change.
   impact 4/5 · effort 2/5 · touches: demo + client prompts, `nevamis-engine/scripts/agent-regression.mts`, `nevamis-site/demo.html`

29. **AGENT-PRODUCT-QUALITY-029 — Use caller ID to recognize repeat callers.** ElevenLabs exposes the inbound caller number as a system variable; today every call starts from zero even when the same customer rang yesterday. Pass caller ID into the client agent and, when the engine has a prior `call_intake` row for that number, greet accordingly ("hi, calling about the water heater?") and skip re-collecting the callback number. It is the single most human-feeling improvement available, and it shortens calls, which directly reduces the client's metered minutes.
   impact 4/5 · effort 3/5 · touches: ElevenLabs dynamic variables, `nevamis-engine/src/domain/call-intake.ts`, client agent prompts

30. **AGENT-PRODUCT-QUALITY-030 — Add a "captured but not booked" outcome so partial calls still count as wins.** The `appointment_outcome` field allows booked / transferred / message / none, which lumps "caller gave a full name, number and job description then hung up before booking" into the same bucket as a hang-up at hello. Split it: `lead_captured` when name plus number plus job exist without a booking. Pilot success is measured on captured leads (QUALITY-SCORECARD row 1 targets ≥90% of connected calls producing a captured lead), so the taxonomy has to be able to express the thing being measured.
   impact 3/5 · effort 2/5 · touches: `nevamis-engine/src/domain/agent-draft.ts`, `src/domain/call-intake.ts`, `docs/pilot/day7-pilot-report-template.md`

## D. Voice, latency and turn-taking

31. **AGENT-PRODUCT-QUALITY-031 — Measure time-to-first-audio and publish a baseline.** QUALITY-SCORECARD row 8 lists latency as unmeasured and the production checklist's only latency gate is "feels like a normal phone conversation" — a judgement, not a number. Place twenty calls to the demo line, record each with a stopwatch or an audio capture, and log three numbers: greeting latency after answer, median inter-turn gap, and the worst gap during a `book_meeting` call. Write the baseline into `AGENT-REGRESSION-2026-07-27.md` so any future model, prompt-length or voice change can be judged against it instead of against a memory of how it felt.
   impact 4/5 · effort 2/5 · touches: `nevamis-engine/docs/AGENT-REGRESSION-2026-07-27.md`, `nevamis-engine/docs/QUALITY-SCORECARD.md` (row 8)

32. **AGENT-PRODUCT-QUALITY-032 — Add a spoken filler immediately before every tool call.** `check_booking` then `book_meeting` are two sequential network round-trips to Cal.com in the middle of a phone call, and the current prompt has the agent go silent through both. Add an explicit instruction: say a short natural line ("let me check the calendar, one sec") *before* invoking the tool, never after. Dead air is the tell that makes callers say "hello? hello?" and is a far bigger perceived-quality lever than shaving milliseconds off inference.
   impact 5/5 · effort 1/5 · touches: demo agent prompt (BOOKING PROCEDURE, TOOL DISCIPLINE), client templates

33. **AGENT-PRODUCT-QUALITY-033 — Test a 5-second turn timeout for client agents against the current 7.** Seven seconds is defensible on a sales demo line where callers pause to think, but on a trades line the caller usually knows exactly what they want, and seven seconds of silence after they finish speaking reads as a frozen system. Run ten calls at 5 s and ten at 7 s on the staging agent, score interruption-of-thinking-callers against perceived-lag, and set the client default deliberately rather than inheriting the demo's value.
   impact 3/5 · effort 2/5 · touches: ElevenLabs turn settings (client agents), `nevamis-engine/docs/AGENT-CHANGE-CONTROL.md`

34. **AGENT-PRODUCT-QUALITY-034 — Test barge-in behaviour against real job-site noise.** The prompt's top-priority rule is "the instant the caller starts speaking, STOP immediately", which is right for a quiet room and potentially wrong next to a running compressor, where every noise spike can false-trigger a yield and leave the agent stuttering. Record three ambient beds (truck cab at highway speed, shop with a compressor, windy exterior), play them under ten staging calls, and tune interruption sensitivity so the agent yields to speech but not to noise. This is the failure mode most likely to make a trades owner say "it doesn't work on my jobs".
   impact 4/5 · effort 3/5 · touches: ElevenLabs turn/interruption settings, `config/elevenlabs/nevamis-agent-test-cases.md` (new case)

35. **AGENT-PRODUCT-QUALITY-035 — Add a post-interruption recovery rule.** Catalogue case 19 checks that the agent answers the interrupting question and does not resume its abandoned sentence, but it does not check that the abandoned *information* still gets delivered. Add: after handling an interruption, if the abandoned turn contained something the caller still needs (a price, an available slot), deliver it in one short sentence once the interruption is resolved; otherwise drop it. Without this the agent either repeats itself robotically or silently loses the thread.
   impact 3/5 · effort 1/5 · touches: demo + client agent prompts, `nevamis-engine/scripts/agent-regression.mts`

36. **AGENT-PRODUCT-QUALITY-036 — Run a blind voice test with five real trades owners before locking the client-agent default.** The current voice (`gJx1vCzNCD1EQHT212Ls`) was chosen once and never compared. Record the same 30-second scripted call in three or four candidate voices, play them unlabelled to five Edmonton trades owners during outreach calls (which doubles as a conversation opener), and pick on their votes, not yours. Ask one specific question — "would you let this answer your phone?" — rather than "which do you like".
   impact 3/5 · effort 2/5 · touches: ElevenLabs voice config, outreach conversations, `nevamis-engine/docs/agent-prompts/demo.md`

37. **AGENT-PRODUCT-QUALITY-037 — Evaluate `eleven_flash_v2_5` against the current `eleven_flash_v2`.** The TTS model was set during the initial build and never revisited; v2_5 trades a small latency delta for broader language coverage and different prosody. Run the same ten-scenario staging suite on both, compare the measured latency baseline from idea 31 and a blind naturalness rating, and either switch or write one line in the change-control doc saying it was evaluated and rejected. Either outcome ends a standing open question.
   impact 2/5 · effort 2/5 · touches: ElevenLabs TTS config, `nevamis-engine/docs/AGENT-CHANGE-CONTROL.md`

38. **AGENT-PRODUCT-QUALITY-038 — Document why temperature is 0.0, or test 0.2.** Temp 0.0 is the right call for pricing accuracy and is why the pricing regression passes so reliably, but it also flattens the warmth the TONE section asks for. Rather than guess, run the pricing and pilot P0 scenarios five times at 0.2 on staging; if factual accuracy holds at 5/5, the naturalness gain may be worth it, and if it doesn't, write the result down so it never gets relitigated.
